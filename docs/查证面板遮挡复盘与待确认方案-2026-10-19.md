# 查证面板遮挡：复盘与待确认方案

2026-10-19。覆盖式定位已在主站移除，但用户再次指出滚动同步回退、布局与视觉不合格，当前整体交互未验收。下文候选阶段记录保留原状，最终实现与复测见末节。此前“查证不挤正文且可原位返回”的自动检查通过，不足以支持体验验收结论，现撤回“查证交互已验收”的判断。

## 已确认的现场与根因

用户在Safari《五色棒》页面打开查证与背景，固定面板遮住正文右侧。随后实际读取Safari页面与截图确认：下一段的长句直接被面板截断。这不是仅有审美差异，也不是用户操作不当。

`web/app/globals.css` 的桌面规则把 `.reader-panel` 固定在右侧，宽420px；正文仍居中且未预留面板所占空间。窄屏规则把面板固定在底部，高70vh，同样可遮住正文。`.with-panel` 没有实现同时可读的布局。

旧测试只检查面板在视口内、关闭按钮位置、打开前后正文宽度与纵坐标不变、焦点返回和记录保留。宽度不变在这个实现里恰好放过了覆盖；这些条件不能代表读者仍看得见正文。此前测试虽然确实执行，验收条件仍有重大缺漏。

## 当前处理

1. 保留已有内容和本地阅读数据，不通过清空记录掩盖故障。
2. 修改 `web/scripts/verify.mjs`：删除“正文宽度必须不变”的错误要求，检查可见文字行与面板的实际相交，并加入1324px《五色棒》的用户复现路径。
3. `npm run verify -- 连续阅读` 当前明确失败：1324px查证栏遮住“过了几个月，灵帝所宠爱……”的正文。之前也确认390px遮住“士卒死伤很多”。失败是当前产品状态，应保留到真正修复。
4. 停止未经确认的主站布局、动效替换。用户明确指出“没有找我人工确认”；下一步以可操作的候选确认交互，再实现主站修复。“继续任务”不自动等于同意任一候选。

## 候选预览

预览源码：`design/interaction-review/source-panel-review.html`。它是独立交互样机，不是主站修复版，也没有接入用户阅读存储。

- 并排查证：宽屏正文与查证分栏；窄屏在段后展开，不压在正文上。
- 段后展开：所有宽度均在对应段落后展开，正文宽度保持一致，后文随之下移。

两者均可开关，切换依据、原文、背景、映射与人物，关闭或Escape返回触发入口。动效只用于段后展开，尊重减弱动态效果设置。实际实现还须解决长篇正文的锚点保持、长引用滚动、所有来源跳转及返回；样机通过不能替代这些验收。

已在Safari新标签页核对并排候选的显示、原文切换与关闭后焦点返回；原主站标签及存储没有清空。候选在320、390、768、1024、1440宽度、正常与减弱动态效果下分别检查两种布局，共20组，页签、开关、Escape、正文与面板不相交及横向不溢出通过。该检查没有冒称原生Safari覆盖所有尺寸，也没有冒称主站全部28篇已通过新交互验收。

参考[Apple分栏视图指南](https://developer.apple.com/design/human-interface-guidelines/split-views?changes=_6)中相邻面板与窄环境适配原则，以及[Material侧面板指南](https://m2.material.io/components/sheets-side)中共同占据布局空间的侧面板说明。它们用于选择候选机制，不等于用户已经同意方案。

## 用户选择后的主站修复与复测

用户在交互候选中选择“并排查证”，随后再次指出Safari《燕国危局》仍遮挡正文。本轮直接将该方案落实主站，不再把独立样机当作主站修复。历史上的失败结果与责任记录保留，不作删除。

- 1081px及以上：正文与查证实际占据相邻网格列；查证栏在自己的列内吸顶。删除右侧fixed定位，正文不再延伸到查证栏下面。
- 1080px及以下：唯一的查证面板挂载在当前叙事段落后面，后文自然下移；删除底部fixed定位。复习卡查证在原卡末尾展开，桌面也不跳回远处的正文栏。
- 长原文在面板内部滚动；保留五个页签、引用定位、返回和Escape关闭。开关记录触发位置，关闭恢复位置和键盘焦点；不清空用户记录。另修正关闭后的空白16px与浏览器自动滚动锚定叠加造成的位置偏移；首次从入口引用挂载正文后，观察排版尺寸变化并校正查证位置，避免字体就绪后标题落到导航栏下。手机短依据按内容高度展开，长内容才内部滚动。
