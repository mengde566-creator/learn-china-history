# 观史定时任务执行与优化记录

这份记录用于连续接手、选择下一步和检验效率改进。完整目标以[观史完整目标与验收](观史完整目标与验收.md)和用户最新指令为准；本记录不替代逐篇历史终审。

## 执行约定

- 开始先检查 Git、最新人工指令、完整验收清单、最近一轮记录与实际页面。确认正在验证的服务属于本项目，记录端口、构建 ID 和改动版本；保留原有他人改动及用户数据。
- 优先修复阻断阅读、内容错误和数据误写，再推进尚未终审的篇目。每项先写可复现问题与验收条件；不能只检查后继续留下可以解决的问题。
- 检查分为“通过／失败／未运行”。共用阅读组件、解析器、进度或数据结构改动须补相关全站回归。历史内容变更须复读关联正文、背景、白话、复习及追问，并注明实际核对的资料版本与结论边界。
- 代码、内容、构建及影响范围一致的有效证据可复用；有新改动、失败或未解决疑点时重验。不能复用旧构建结果证明新构建，也不能并发重建同一产物或更换正在验证的服务。
- 每轮必须留下具体优化策略，写清适用条件、行动、可检查的成败标准；下一轮先核查是否执行、是否有效。无需每次重写自动化配置，应先改善具体执行方法。
- 已验证的独立改动保存本地提交，不擅自推送或发布。暂时无变化也记录原因和可执行下一步，不向用户反复汇报空检查。

## 每轮追加模板

1. **时间与版本**：起止时间、时区、基线提交、工作区已有修改、服务端口、生产构建 ID；关键文件哈希或可定位差异。
2. **本轮目标**：完整清单中的哪一项、为何优先、复现步骤与验收条件。
3. **实际结果**：完成哪些修改；未完成哪些；资料版本及归属；是否涉及现有阅读数据。
4. **验证证据**：命令、退出状态、影响范围、真实页面及截图；注明未运行项和证据局限。长命令预先用 `time -p` 计时；没有计时的步骤不能事后虚构精确耗时。
5. **效率复盘**：重复检查、等待、误报或定位瓶颈；上一轮策略是否奏效，并列依据。
6. **下一轮优化策略**：具体行动、适用条件、预期改进及检验方式；明确下一项未完成工作。
7. **保存状态**：本地提交、剩余工作区改动；提交后可以用该记录所在提交定位结果，不为自填提交哈希循环追加提交。
