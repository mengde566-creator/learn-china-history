## 目录结构

```
content/
  README.md              本文件 —— 写作规则（全局）
  审校记录.md             审校过程（全局，不进产品）

  people/
    jingke/              一个人物 = 一个目录
      person.md                   人物：时代 / 出处 / 简介 / 关键时点
      source.md                   底本（编号从 001 起，段数以 `npm run check` 的输出为准）
      stories.md                  故事一览（每篇一行，id 对应 stories/<id>.md）
      cast.md                     本篇人物（高渐离、太子丹…）的知识边界
      stories/<id>.md             故事内容
      seeds/<id>.md               对话种子（预置问答）
      cards/<id>.md               复习卡
      source-layers.json          可选：同一编号内的正文、注、引书及白话分层
      gloss.md                    逐段直译（「完整资料页」用）
      gloss-parts/*.md            直译的写作分片，由 `merge-gloss.mjs` 合成 gloss.md
      assets/                     图片（内容里只写文件名）
    caocao/             ← 以后加人，只加一个目录
```

**不是每个人物都有全部文件。** `cast.md` 只有荆轲有（曹操那十篇没有人物卡）；
`gloss.md` / `gloss-parts/` 是后加的，没做直译的人物就是没有——**缺了不报错**。
哪些文件是可选的，写在 `web/scripts/build-content.mjs` 里。

### 旁批摘句与完整底本

情节点的「原文」栏仍指定主要编号，「依据」栏保留所有相关编号。某个编号很长、只需先展示对应几句时，可在同一张元数据表另加一行：

```text
| 摘句046 | 綽始制文案程式，朱出墨入，及計帳、戶籍之法。 |
```

多来源可各加一行「摘句047」等，不能重复同一编号。摘句必须是该编号内的连续原句，且编号已在本段引用列表里；错配、拼接、空句会阻止编译。没有摘句时沿用原有全文或「原文」栏摘句。页面先展示摘句，原编号、出处和其他来源保留，完整上下文仍可展开；不能用摘句删去与叙述不同的后文。

### 层级

```
时代（分组标签，不做成一级页面）
  └ 人物        荆轲 · 曹操 · 高欢 · 宇文泰 · 刘裕 …
      └ 故事    每人 7 ～ 上百篇
          └ 情节点   故事内部，不导航、不编号
```

**「时代」为什么只是标签**：只有 5 个人时它是个空层，50 个人时才需要独立成页。做成标签，两种规模都成立。

**「阶段」为什么可选**：篇数少（荆轲）直接列就行；到了几十上百篇（曹操）才需要按「洛阳 / 讨董 / 兖州」这类分段。它是人物页内部的分组（`stories.md` 的「## 故事一览」**里面**用 `### 阶段名` 分段），不是独立层级。

> ⚠️ **必须是三级标题，而且必须写在「## 故事一览」里面。**
> 早先这份文档写的是 `## 阶段名`——那是错的：二级标题在「故事一览」这里意味着
> **这一节结束了**，阶段里的故事会一条都不进列表，**而且不报错**（实测过，
> 校验还报"全部通过"）。现在编译器会拦下这种写法并报错。

**「情节点」为什么不是层级**：它是拆解故事时的工具，用户不需要知道——界面上也不出现。

## 批量改动之前，先提交（这条是用一整篇正文换来的）

**任何会改很多文件的脚本，跑之前工作区必须是干净的。** 不是「最好干净」，是**必须**。

> 🕘 **历史（2026-10-15 的事故记录）**——下面这段是一次真实的丢东西过程，
> 保留下来是为了说明规则是怎么来的，不是一个当前待办。

2026-10-15 我违反这条，一次丢了东西，代价如下：

```
① 一个子智能体刚做完一整篇正文（9 个情节点、419 行），编译全绿 —— 我没提交
② 我写了一个全库重编号脚本，它**不是幂等的**（映射表里 012 既是目标又是源），
   我跑了两次 → 31 个文件被改坏
③ 唯一的退路是 git checkout -- content/people/caocao/
④ 那条命令恢复整个目录 → 未提交的那篇正文一起没了
```

**git 只保护已经提交的东西。** 工作区里的改动，`git checkout --` 一过就没了，
而且 git 里从来没有过它，所以**找不回来**。（`git stash` 本来能救——它是「收起来」，
`git checkout` 是「扔掉」。我用错了那个。）

更刺眼的是：我在回滚前把目录 `cp` 到了 `/tmp`。**那个动作说明我已经感觉到危险了——
而正确的反应是 `git commit`，不是 `cp` 到临时目录。**

> **当你觉得需要手动备份一下的时候，那正是该提交的信号。**

### 三条规则

1. **跑批量脚本之前先提交。** 工作区干净才允许跑。
2. **子智能体报绿 = 一个提交点。** 当场提交，不攒着「这一批做完再一起提」。
3. **`git checkout --` / `reset --hard` / `clean` 之前先看 `git status`。**
   有未提交的东西就停下。

### 机械化的那一道

第 1 条做成了代码，不靠记性：`web/scripts/lib/guard.mjs`。
任何批量脚本开头调用它，工作区脏就**拒绝执行**：

```js
import { requireCleanTree } from './lib/guard.mjs'
requireCleanTree('全库重编号')   // 脏就退出，什么都不做；真要跑加 --force
```

**脚本自己也要防重复跑**（幂等或加戳）——今天那个脚本如果开头有这道检查，
后面两个错都不会发生。

## 加一篇故事要做什么

**已实测：只补数据文件，不改代码。** 曹操那十篇就是这么加满的。

原来最耗人的不是写白话，是**串线**：门口每一行要在「逐行依据」里有一行对应，
每段情节点要挂对原文和依据编号，「依据映射表」还要把本篇说法再列一遍——
少一处编译器就红，而红的地方常常不是写错的地方。

现在这四步都有工具：

| # | 做什么 | 命令 | 必填 |
|---|---|---|---|
| 1 | 在 `stories.md` 的「故事一览」加一行，**把「原文」一列填上** | 手写 | ✅ |
| 2 | 底本里没有的句子，从参考文本里找 | `npm run ref-grep -- 将据成皋` | 视情况 |
| 3 | 生成骨架：门口、逐行依据、情节点、映射表**一次成型** | `npm run new-story -- caocao 04-xingyang` | ✅ |
| 4 | 填白话、背景卡、在场人物 | 手写 | ✅ |
| 5 | 建 `seeds/<id>.md`（对话种子） | 手写 | ⬜ 可选 |
| 6 | 建 `cards/<id>.md`（复习卡） | 手写 | ⬜ 可选 |
| 7 | 图片放进 `assets/`，在内容里填文件名 | 手写 | ⬜ 可选 |

两步收尾，都必须跑：

```bash
npm run check           # 结构、标记、行话、引文、编号
npm run check-sources   # 原文是不是和参考文本逐字一致
```

### `npm run ref-grep` —— 找原文

参考文本在 `.refs/`（`npm run refs` 取）。它已经做好了繁转简和跨底本定位，
所以找句子从「回忆 + 找人核」变成「检索 + 抄」。

**不要凭记忆写原文。** 实测过：两路独立回忆加上一个审核子智能体，
三票都把一个出处记成了《魏书》，实际是孙盛《异同杂语》——
只有逐字比对查得出来。而 `check-sources` 是**免费的**。

### `npm run new-story` —— 生成骨架

它读两样东西：`stories.md` 那一行（篇名、情境、转折、原文范围），
和 `source.md` 里那个范围的正文。然后生成一篇结构完整的骨架：
门口七行、逐行依据表、每段底本一个情节点、映射表、在场人物表。

**它只生成结构性的东西**，白话一句都不写——那部分是人干的活。

生成完**编译必须是红的**。骨架里的「（白话待写）」会被行话检查拦住，
这是故意的：**一篇没写完的故事以「已完成」的样子混进产品，是最坏的一种情况。**
（这条检查是加骨架的时候才发现缺的。）

情节点可以合并、拆开、删掉——骨架是起点，不是模具。

**前提**：这篇故事用到的原文段落必须已经在 `source.md` 里。不在就先补，
补完立刻 `npm run check-sources` 验。

**可选的缺了会怎样**：没有种子 → 故事页不显示「你想说什么」入口（不会给一个点了没反应的按钮）；没有复习卡 → 显示「本篇暂无复习卡」。**不会崩，也不会显示空壳。**

### 故事一览的顺序就是读的顺序，两条编译器会拦

**这一条是用户读出来的。** 曹操前十篇里，「五色棒」（174 年，他二十岁）
排在「刺董」（189 年）**后面**——因为刺董是先写的那一篇，编号就给了 `01`。
数字、文件、引用全都自洽，编译器全绿，**只有读者看到的顺序是错的**。

`stories.md` 那张表不是索引，是**目录**。两条规则：

| # | 规则 | 为什么 |
|---|---|---|
| 1 | 表里的 `id` 必须顺着排 | 文件按 id 排序。行序和 id 打架时，页面顺序就是错的 |
| 2 | 同一个「### 分组」里，**时间必须递增** | 表就是读的顺序。倒着排，读者会先看到结果再看到原因 |

改编号别手改——id 出现在文件名、故事一览、种子、复习卡、交叉引用和文档里，
漏一处不会报错，只会让一篇故事静静地变成孤儿。用：

```
npm run renumber -- caocao 01-wusebang=02-wusebang 02-cidong=01-cidong
npm run renumber -- caocao --dry 01-a=02-b     # 只看要改什么
```

两两交换它能处理（先落到临时名再落目标名）。**它改完会提醒你行序还是旧的**——
因为改行序是内容判断（按时间排），工具不替你做。改完必须 `npm run check`。

第 2 条只认**纯数字的公元年份**（`174`、`189`）。「同年」「前 227 年」
「前 232 – 前 228」这类写法一律跳过：那些年代本身就还没核过（荆轲那一页
写着「需另行核对」），拿没核实的文字当判据，闸门迟早会误报。
**跳过不等于不管**——写成那种形式时，顺序要你自己看一遍。

### 故事一览和故事文件，两处必须对得上（编译器会拦）

一张故事卡片上写着「曹操刺董」，点进去是五色棒——这种事原来的编译器**一声不响**，
因为文件里那两处声明根本没有任何代码去读：

| 文件里的东西 | 原来谁在读 | 现在 |
|---|---|---|
| 第一行 `# 02-cidong · 曹操刺董` | **没人**。页面上的篇名一律取自 `stories.md` | 必须等于 `stories.md` 那一行的篇名（`★` 不计） |
| 前表 `\| **原文** \| 008 \|` | **没人**（只有「地点」被读） | 必须等于 `stories.md` 的「原文」那一列 |
| 每一段引的编号 | 没人查它和范围的关系 | 必须落在这一篇声明的范围里 |
| `seeds/`、`cards/` 第一行的序号 | **没人** | 必须等于文件名的序号 |

第四条拦的是「说了小说不说是哪一本」的兄弟问题：`cards/06-yishui.md` 一直写着
`# 05 · 复习卡`，`seeds/02-cidong.md` 一直写着「场景 01」——**标题不渲染，
所以错了没人看得见**，可它是你回头找东西时唯一的路标。

**第三條有个副作用要知道。** 「本篇原文范围」的判据是「这一段会摊在读者面前的原文」，
不是「这一段讲的事」。荆轲那几篇是**链式结构**（每篇的出口就是下一篇的入口），
所以 03 的范围要从 `022` 起（第一段要重说 `025`，第二段的依据又要回到 `022`），
不是从 `026` 起。范围写小了会出**静默的错**：「依据」面板里那一句引文是空的——
读者看到一对空的引号加一个编号，而编译器原来不响。

### 写种子和复习卡时，编译器会拦什么

| 拦什么 | 为什么 |
|---|---|
| 第一行标题里的序号必须等于文件名的序号 | 标题**不渲染**，是你回头找东西时唯一的路标。`cards/06-yishui.md` 曾经写着「# 05 · 复习卡」 |
| 全篇凡是「场景 NN」「故事 NN」都要对得上 | 只查第一行不够：`cards/02-cidong.md` 的二级标题写着「场景 01」，第一行却早改成了 02 |
| 每条种子都要有标记 | 没有徽章，读者就失去了判断「这句话站得住多少」的入口 |
| 「标记」行读不出标记 → 报错 | 见下 |

**关于「标记」行。** 它**可以带小字**：`| 标记 | ○ 外证 |` 是合法的，
编译器取第一个字符。这一条原来是坏的——正则只认 `| 标记 | ○ |` 一种写法，
写成带小字的那种会**静默丢掉标记、编译全绿**，而图例恰恰在教作者写「○ 后面跟一个小字」。
**编译器在罚它自己教的写法**，而且罚得无声无息。现在两样都收，读不出的直接报错。

**三个容易踩的坑（都不是报错，是报错报得让你莫名其妙）：**

1. **依据行只引一个编号时，该行所有较长的「」引文都必须逐字出自那一段**——
   包括你自己写的按语。**按语不要放进 `「」` 里**：`「」` 是原文的位置。
   你自己的话写成 `**粗体**` 是个好习惯，但要知道——
   **它不渲染。界面不显示粗体。** 它只是给下一个读这份文件的人看的记号：
   「这句是作者的话，不是原文」。
2. **裸的三位数字会被当成原文编号**。写「5000 人」会报「引用了不存在的原文编号 500」
   （这一条已于 2026-10-14 修好：数字前后都有边界才认。
   实测「公元 189」「公元 189 那一年」都过；**不带「公元」也不带「年」的裸三位数**
   仍然会被当成编号——「189 那一年」报错，「189 年」不报。）
3. **`统计` 那一节的标记分布表没有任何校验**，数错了只有人眼能发现。

### 写故事正文时的五条硬规则（编译器会拦）

曹操那篇（`people/caocao/stories/02-cidong.md`）是拿架构做实验时踩出来的。五条都写进了 `build-content.mjs`，违反哪条都会红。

| # | 规则 | 踩过什么 |
|---|---|---|
| 1 | **每个情节点的白话都要逐句对得上它的标记。** 标 ◆ 就只写底本里有的；推出来的话要么删，要么整段标 ○ 并在 `依据` 里给链条 | 三段 ◆ 白话里各夹一句底本没有的话（「朝里没人敢说话」「董卓看上了曹操」「走到陈留散尽家财起兵」），而最后那句在映射表里标的是 ○——同一句两种标记，这张表就废了 |
| 2 | **原文进正文必须整行用「」包起来。** 后面可以带句号，但前面不能加「他唱：」 | 引文补个句号、或写成 `他唱：「……」`，形状判据失效，它就从「原文」块掉成普通白话——没有牌子，也不要求白话回译，读不懂文言的读者卡在那一句上 |
| 3 | **情节点标题写全**：`### 情节点 3 · 东归`。编号、「·」、小标题三样都不能少 | 写成 `### 情节点 · 东归` 会被当成上一段的正文，第 3 段并进第 2 段，段数少一个而校验报"全部通过" |
| 4 | **门口的情境铺陈也是入戏内容**，不许谈书、谈读者（「这一段，《武帝纪》里没有」）。要谈书，写在背景卡和映射表里 | 那句话写在情节点里被用户点名「破坏氛围感」；挪到背景卡就是「七宝刀」那一张的全部内容 |
| 5 | **读者可见的地方不留写作待办**（「需补编号」「待补」「C 级」） | 映射表的依据栏留过一句「需补编号」，读者看到的是一句没头没尾的施工告示 |

**关于第 2 条怎么判**：形状判据之外还有一条反查——正文里只要有连着 12 个字和底本逐字相同、又没挂牌子的行，就报错。门槛定 12 是量出来的：8 个字会误伤 6 处正常的白话（「高渐离击筑荆轲和」9 字、「秦并天下立号为皇帝」9 字这类顺手留下的文言短语读者看得懂）。

## 人物页也要交代底本

故事的「原文」范围写在 `stories.md` 那一列。**人物页原来什么都没有**——于是
曹操的引子讲了七件 `source.md` 里没有的事（那份底本当时只有 4 段，全是刺董那一刻），
其中「走到赤壁，烧掉了自己的船」还是魏方单方面的说法，正文只有「乃引军还」。
编译器一路绿灯。

现在 `person.md` 标题下的元数据表里必须有一行：

```
| **底本** | 001–019 |
```

编译器查两件事：**声明了没有**（「他是谁」「引子」非空就必须有），
**范围里的编号在 `source.md` 里存不存在**。它保证不了逐句对得上——
但有了范围，写的人就得先回答"这些事凭什么"。

> 这条规则和「所有内容必须能回溯到编号」是同一件事。规则一直写着，缺的是机制。

## 一个人可以有好几本底本

**曹操不是一本书里的人。** 同一件事，正史、注家、小说给的是三个版本——
「曹操刺董」就是最典型的一处：正史里没有那一刀，演义里有。

`source.md` 按**底本**分小节，底本按**档次**分号段：

```markdown
## 底本一 · 正史 ·《三国志·魏书·武帝纪》
| 编号 | 原文 | 优先级 |
| 001 | 卓到，废帝为弘农王而立献帝，京都大乱。 | A |

## 底本二 · 注 · 裴松之注
| 编号 | 原文 | 出处 | 优先级 |
| 201 | 〔曹瞒传曰〕：太祖一名吉利，小字阿瞒。…… | 裴松之注引曹瞒传 | B |

## 底本三 · 小说 ·《三国演义》
| 编号 | 原文 | 出处 | 优先级 |
| 401 | 坐中一人抚掌大笑曰：「满朝公卿，夜哭到明，明哭到夜，还能哭死董卓否？」…… | 第四回 | A |
```

| 号段 | 档次 | 意思 |
|---|---|---|
| `001–199` | **正史** | 底本正文 |
| `201–399` | **注** | 注家引的别史——是史料，只是不在正文里 |
| `401–599` | **小说** | 《三国演义》这类，**不是史料** |
| `601–799` | **野史** | 非官修的记载、传闻 |

**光看编号就知道是哪一档。** 编译器会拦「编号落在 `201–399`（注）却挂在正史底下」这种错。
判据只有一份实现：`web/scripts/build-content.mjs` 的 `bandOf`，
完整资料页（`app/p/[person]/source/page.jsx`）用的是同一个口径。

> ⚠️ **2026-10-15 号段从「每档 100 个」加宽到 200。** 旧写法 `0xx / 1xx / 2xx / 3xx`
> 已经不够用——《武帝纪》全收要 112 段正文 ＋ 111 段注，100 个位置装不下。
> **看到旧文档写 `0xx`，按上表换算**（`0xx`→`001–199`、`1xx`→`201–399`、
> `2xx`→`401–599`、`3xx`→`601–799`）。

**一个档次里可以有不止一本书。** 曹操的正史档现在是两本：

| 底本 | 书 | 号段 |
|---|---|---|
| 底本一 | 《三国志·魏书·武帝纪》 | `001–112` |
| 底本四 | 《三国志·吴书·周瑜传》 | `113–116` |

底本四是**对方的传**：赤壁那一仗，魏方（`065`）只有「与备战，不利。于是大疫，
吏士多死者，乃引军还」——船、火、风一个字都没有；**火攻记在吴人的传里**，
所以收进来作对照。新收的一本**接在正史号段后面编号，不动前面任何一段的编号**。

> **段数不要在文档里抄。** 每本底本收到哪一号，看 `source.md` 各小节表里第一行和最后一行；
> 全库各是多少段，`npm run check` 会印出来。

不写 `## 底本` 小节的行，默认归 `person.md`「出处」那一本的正文——
荆轲的 `source.md` 一个小节都没有，照旧。

**四列表**（编号｜原文｜出处｜优先级）用于同一本底本里各条出自不同的书——
曹操的「底本二 · 注」整档都是这样：111 条分别引自《曹瞒传》《世语》《异同杂语》
《英雄记》《献帝春秋》《山阳公载记》……逐条在「出处」栏写明是哪一本。
三列表（编号｜原文｜优先级）还是老样子，正史和小说两档用它。

> **示例里的原文只是摘录**（`……` 处省略了），**抄的时候去 `source.md` 取全文**。

## 凡是底本，界面上都要写出书名

**这条是被用户当场问出来的。** 曹操「刺董」那一篇里，演义那几句在界面上标着
「`◇` 出自小说」——**哪个小说？** 同一个面板上，正史那几句底下写着
「《三国志·魏书·武帝纪》正文 001」，演义那几句底下只有「第四回 201」。
一边有书名，一边没有；读者没法判断这一句该不该信。

同一个毛病当时有四处：

| 界面上的位置 | 原来印的 | 现在印的 |
|---|---|---|
| 「依据」面板，标记旁边 | `◇` 出自小说 | `◇` 出自小说《三国演义》 |
| 「依据」面板，引文底下那行 | 第四回 203 | 《三国演义》第四回 203 |
| 「原文」面板的分节标题 | 小说 · 不是史书，出自小说 | 小说 · 《三国演义》 · 不是史书 |
| 图例 | 出自小说（《三国演义》）——**写死的** | 出自小说《三国演义》，跟着这一页的底本走 |

**怎么保证不再犯：**

1. **书名的唯一来源是内容。** `## 底本三 · 小说 ·《三国演义》` 这一行里的书名，
   和 `person.md` 的「出处」那一行，是仅有的两个出处。界面不许自己编一个，
   也不许写死一个（图例原来写死《三国演义》——曹操那一页碰巧是对的，
   换个人物就是假话）。
2. **小说这一档的出处要接上书名。** 四列表的「出处」栏写的是「第四回」，
   编译器会在前面接上底本名，变成「《三国演义》第四回」。正史和注不用接：
   正史那一栏本来就是整本书名，注那一栏写的是「裴松之注引孙盛《异同杂语》」。
3. **映射表里引了小说或野史，同一行就要写出书名。**
   不许写「（同上）」——读者从表格中间往下看，不知道那是谁的第四回。编译器会拦。
4. **底本不能没有名字。** `## 底本三 · 小说` 这种半截标题、
   或者 `person.md` 里「出处」空着，都会报错。原来那个兜底词是
   「未署名的底本」，它会原样印到「原文」面板的分节标题上——
   荆轲那一页就这么印了很久，因为调用处取的是 `meta['出处']`，
   而 `parsePersonMeta` 返回的键叫 `sourceBook`。**取错了键，一路 undefined，全绿。**
5. **拼出处这条规则只有一份实现，在 `web/lib/cite.mjs`。**
   编译器（`build-content.mjs`）和骨架生成器（`new-story.mjs`）都 import 它。
   **这一个是血的教训**：规则原来只写在编译器里，生成器自己算了一份不一样的，
   于是加了一道「引了小说就得写出书名」的闸门之后——
   `npm run new-story` 生成的文件第一次 `npm run check` 就红，
   报错还指着生成器刚写的那一行。**「加一篇故事」这条主干道被自己堵死了。**
   同一个词在两个脚本里含义不同，本身就是隐患。
6. **「别的书」不止小说。** `◇` 的定义是「出自底本正文之外的另一本书」——
   小说和野史都算（`3xx` 号段就是给野史留的）。这个语义一直写在编译器的注释里，
   但实现只认小说档：真加了野史内容，挂 `◆` 被语义否定、挂 `◇` 又被判成
   「不是小说」，两条路都堵死。现在两档都走 `◇`，界面按底本的档次写
   「出自小说《三国演义》」或「出自野史《曹瞒传》」。

## 「底本」和「原文」是两个词，不能互换

读者面前这两个词都在用，它们指的是不同的东西：

| 词 | 指什么 | 出现在哪 |
|---|---|---|
| **底本** | 这一页所依据的**那本书**（《三国志·魏书·武帝纪》《史记·刺客列传》《三国演义》） | 「底本（这一页所依据的书）N 段，分 4 本…」「底本不载」 |
| **原文** | **引出来的那段文字**本身 | 「原文」页签、`◆` 出自原文、原文块、原文台词、白话回译的对照物 |

> 🕘 **历史措辞**：这段话原来还举过一个例子「底本由 AI 依记忆写出」（2026-10-13 的实情：
> 底本最初确实是凭记忆默写的，之后才逐字核对）。**这类句子现在有两个问题，别再新增：**
> ① 读者看到的版本里还带着数字，而数字已经过期（见下文「已知缺口」）；
> ② **AI 不在产品范围里**（2026-10-17 定），读者面前谈 AI 会让「这里有没有 AI」变成一个问题——
> 现在的答案是「没有」。要交代底本来源，写「据公版电子本逐字核对」这一层就够。

**判据一句话：说「这本书没有记载 X」用底本；说「这段文字里没有 X」用原文。**

**编译器怎么拦（两条，查的是读者看得见的字段，不是文件的行）：**

| 拦什么 | 例子 |
|---|---|
| 一个词修饰它自己 | `原文底本`、`底本原文` |
| 该用底本却写了原文 | 「原文不载」「原文没有解释」「原文一字不写」（中间插副词也拦） |

**不拦的（都是正常说法）**：「三段原文里没有」「好几本底本」「同一本底本」。

> **为什么不按文件扫。** 第一版写成扫 `content/` 全树，于是要一份一份地排除：
> README 是规则文档（「原文」在它里面是被定义的词）、`source.md` 除底本表都不上屏、
> `stories.md` 只有「故事一览」那一节上屏……排到第三份就该明白：
> 要的不是"哪些文件"，是"**哪些文字读者会看到**"——那正是编译器里那个
> `visible` 列表（行话检查用的也是它）。挂在那里，一个文件都不用排除。

**读者第一次遇到「底本」**：人物页的脚注写着「**底本**（这一页所依据的书）N 段，分 N 本：…」
（段数和本数由 `person.books` 算出来，见 `app/p/[person]/page.jsx`）；
故事页的图例里还有一句完整的解释。**说一次就够，别处不再解释。**

## 标记不止四个（现在是六个）

前四个说的是「这句话在**史料**上站得住多少」。
演义不站在这把尺子上——它不是"更不可靠的 ◆"，是**另一个世界的说法**。

| 标记 | 色 | 含义 |
|---|---|---|
| ◆ | 朱 | 出自原文，可逐字核对（**含注**——书名会跟着显示） |
| **◇** | **紫** | **出自小说，不是史书** |
| ○ | 苍 | 合理推演，附推演链条 |
| △ | 赭 | 史书未载，后世有争议 |
| — | 灰 | 不回答：史书未载、推不出来，或者不在本篇范围内 |
| ⓘ | 中性灰 | **产品说明**：这一条回答的是产品本身，跟史料无关 |

空心对实心，一眼分得开；书名永远跟着一起显示（依据面板、「本篇原文」的分节标题、
门口那一行的来源）。

**编译器两个方向都拦**：引了小说就必须标 ◇；标了 ◇ 就必须真引了小说。
只拦一个方向的话，把小说段落改标成 ◆ 没人管。

**读者看到的**：「原文」页签按底本分节，写法是「**档次 · 书名 · 这一档要提醒什么**」——
「正史 · 《三国志·魏书·武帝纪》」（正史不提醒）、「小说 · 《三国演义》 · 不是史书」、
「注 · 裴松之注 · 不是正文」，各自挂各自的书名。
（**四档都写出书名**，由 `source.md` 的底本小节生成，界面不自己编——
2026-10-14 之前非正史那三档只写档次，书名一个字没有，用户当场问过。）

**为什么必须分开**：`201` 是裴松之注引孙盛《异同杂语》，`401` 是十四世纪的小说。
和正文并排摊成一张单子、同样挂 ◆，读者会以为「闻司徒有七星宝刀一口」是陈寿写的。

## 逐字核对：`npm run refs` ／ `npm run check-sources`

**这是这个项目最要紧的一条检查。** 全部内容都建立在「原文是这样」之上，
而底本最初是依记忆写出来的；在 `check-sources` 之前，全库「已核」段落是 **0**——
不是没核，是**没有可核的东西**。

```bash
npm run refs            # 把公版电子本取到 .refs/（不进版本库）
npm run check-sources   # 逐字比对 source.md 和参考文本
```

参考文本是公版电子本，谁都能重新下载、自己复核一遍：

| 电子本 | 用来核 |
|---|---|
| 《三國志》#25606（**含裴松之注**） | 曹操 `001–112`（《武帝纪》正文）、`201–311`（裴松之注）、`113–116`（《周瑜传》正文） |
| 《三國志演義》#23950 | 曹操 `401–409` |
| [`hunterhug/china-history`](https://github.com/hunterhug/china-history)〈刺客列传〉 | 荆轲 `001–093` |
| 《史記》#24226 | 项羽 `001–093`、韩信 `001–065`（这一份**缺〈刺客列传〉**，其余两篇都在） |
| 维基文库《北齊書》卷1–2、《魏書·孝莊紀》、《周書》 | 高欢 `001–038`、宇文泰 `001–072` |
| 维基文库《晋书》卷062（修订号 2629226） | 祖逖 `001–046` |
| 维基文库《梁書》卷32（修订号 1506956，中华书局一九七三年版录文） | 陈庆之 `001–043`（7 处异体异文按校勘表处理） |
| 维基文库《宋書》卷1–3、卷48 | 刘裕 `001–041`、`101–107` |
| 维基文库《宋史》卷401（修订号 2293949） | 辛弃疾 `001–037` |

**全库 七百七十一段全部逐字对得上**——这是 2026-10-20 `npm run check-sources` 的输出
（「对得上 771 · 对不上 0 · 跳过 0」）。**段数会随内容增长，以命令输出为准**；
每本底本各自收到哪一号，看 `refs.json` 和 `source.md` 的底本小节。

哪个底本对哪一段，写在 `web/scripts/refs.json`。**故意和电子本不一样的地方
（校勘）也必须登记在那儿**，一条都不能偷偷改。

**做法的三个要点**（都是踩出来的）：

1. **按小句比，不按整段，也不按整句。** 电子本把裴注夹在正文句子中间，
   有时夹在两句之间，有时夹在一个句子的两个分句之间；我们的底本是「正文连排」。
   切到小句、每片至少 4 个字，两头都盖得住。
2. **繁转简之后才比。** 电子本是繁体。
3. **比对实现是独立的一份**（不复用 `build-content.mjs` 的解析器）——
   复用的话，解析器错了这边跟着错，就白核了。

**它证明的是「我们写的和这份文件一致」。** 口径到此为止，理由见下面「核对口径」一节。

## 图片位

**图片放 `people/<id>/assets/`，内容里只写文件名。** 编译器会同步到站点，并检查文件是否存在——
**写错文件名会在编译时报出来，不会静默显示空白。**

## 对话种子的写作规则

### 一、一条回答只标一个标记

标记表示**这条回答的内容**在史料上是什么地位。**六个，一个都不能混用**：

| 标记 | 用在哪 | 判据（照这个判，不要凭感觉） |
|---|---|---|
| ◆ | 回答的内容直接出自原文 | **整条回答**都能在它引的那几段里逐字找到。回答里只要有一句底本没有的叙述（含舞台指示、「斥候回来报的」这种补白），**整条降 ○**，原句挪去 `依据` |
| ◇ | 出自小说或野史，**不是史书** | 同上；且**必须写出书名**（《三国演义》）。尾部不许挂推演 |
| ○ | 内容是从原文推出来的 | `依据` 里要有链条；推不出来的部分标点说明 |
| △ | 史书未载，且后世有争议 | **只给「同一件事有两种记载」**。外证坐标（公元年、地名、官衔、年号）不属于这一档 |
| — | 不回答 | **只给「读者问的是史料问题，我们决定不回答」**。三种情况都算：史书未载、推不出来、**不在本篇范围内**（读者问的仍是史料问题，只是这一篇不谈）。产品自述、系统说明、外证坐标不得用 — |
| ⓘ | **产品说明**：这一条回答的是产品本身，跟史料无关 | 形状判据：**这一条只有系统说明（围栏里的 ⓘ），没有回答行**。反过来，这种形状必须用 ⓘ |

**`ⓘ` 是 2026-10-14 补的第六个。** 产品里没有自由输入，读者能问的话都来自这份预置清单——
所以他一定会问到产品本身：「这条回答的依据是什么」「这一篇跨了多少年」「你是 AI 吗」。
这些没有史料可站，是产品在说话。
原来它们没有位置，各篇自己找地方：02 借 ◆、03 借 ◆、08 借 —、01 混用 ○/△，
读者看到「你们怎么知道这些的？**◆ 出自原文**」——图例说 ◆ 可逐字核对，
而这一句核不了。全库 58 条是这么标错的，已全部改为 `ⓘ`。
（「你是 AI 吗」这一类条目现在有确定的答案：**这里没有 AI，预置问答是人工写好的静态内容**。
⚠️ 现有种子里还留着「这是一个**没有 AI 的模式**」这种说法——**「模式」这个前提已经取消**，
见下文「已知缺口」。）

**两条最容易写错、审核实测栽过的：**

- **动机题会习惯性地替读者作答。** 题面问「某人为什么**不／没**……」时，
  **先翻这一篇的映射表**。那一行如果是 `—`，这条就只能给两说并置、或者不回答；
  想给 `○`，题面必须改成问**对方那一头**（把「曹操为什么不接这个官」改成
  「董卓为什么给他这个官」——那个 ○ 就站得住了，而当事人那一头整块留给 `—`）。
  02-cidong 就是在这里栽的：种子和卡 1 把映射表标 `—` 的那一问答了，
  而卡 8 又写「史书不回答这个问题」，同一份文件两个相反判定。
- **公元年份一律 `○ 外证`。** 底本里没有公元纪年，「中平六年就是 189 年」
  这一步换算是后世系年。挂在 ◆ 下面＝请读者去核一个核不到的东西。

### 一之补、`**粗体**` 不渲染，这是有意的

内容里写了 2434 处 `**粗体**`，**界面上一处都不显示**。这不是 bug，是决定：

- **它没有技术作用。** 没有任何代码读它——编译器真正认的只有一件事：
  这一段有没有被 `「」` 包起来（包起来的就要逐字核对）。
- **它是给写内容的人看的记号**：「这句是我的话，不是原文」。
  一份种子文件几千行，没有这个记号，下一个人分不出哪句是引的、哪句是评的。
- **为什么不让它渲染**：这套东西已经有自己的强调语言了——
  宋体＝那个时代、楷体＝你、黑体＝工具与考据、朱色＝原文、标记色＝史料等级。
  再加一层粗体会跟它们抢注意力，而 `依据` 那一栏本来就密。
- **要改也不是一行的事**：`RichText` 认粗体，但面包屑、导航、卡片名、背景卡名
  是纯文本渲染（8 处），开了之后每加一个新组件都要记得剥掉 `**`。

（2026-10-14 用户定的：**不渲染**。）

### 一之补二、收尾清单（新写一篇时逐条对）

复习卡的答案表格使用正常的有名表头，例如 `| 来源 | 经过 |`；独立的两列空表头块 `| | |` 用于依据、标记、考点等卡片元数据。两种表块之间用空行分开。答案表的表头或数据行即使写“来源”“出处”“依据”，也属于答案，不作元数据；元数据块中的“内部”行仅供审校，不显示给读者。改写后可运行 `npm run test:cards`（在 `web/` 内）核对表格解析。

这五样编译器**校验不到**（有两样是根本没人校验），全靠人眼——02-cidong 就是
在这里比 01-wusebang 少了几样，两份看起来像两个产品：

1. `## 统计` 里的**标记分布表**：数字要自己数一遍（01「◆23 ○12 △1 —19」、
   03「16/11/0/28」、08「5/25/4/21」都核过是对的；02 整张表没有）
2. 每张复习卡要有 **`| 考点 |`** 行
3. **一卡一标记**，且卡片标记与同一条种子的标记同源
4. 卡片正文引原文也要**落在本篇声明的范围里、同一行写编号**（见下条）
5. 文件头写「`201`–`204` 是第四回」这种话，要和正文实际引到的编号对得上

### 一之补三、同一件事有好几种说法时：主内容展示最眼熟的那一说，依据里列全

读者进来时心里多半已经有一个版本（「赤壁是黄盖烧的」）。产品不该假装那个版本不存在，
也不该把三种说法平铺给他、让他自己挑。

**规则：**

1. **主内容展示最广为人知的那一说**，按它的来源标标记（演义来的就标 `◇`）。
2. **依据里把其余几说列全**，并说明它们在不在底本范围内。
3. **正史不回答的，在依据里写明「正文不回答」**——而不是让整行只挂一个 `—`。
4. **三处标记同源**：映射表、种子、复习卡说的是同一件事，就标同一个标记——
   取**展示的那一说**的标记。

**例子（`09-chibi` 的「谁烧的船」）：**

| 主内容展示 | 依据 |
|---|---|
| 黄盖的火船（`◇` 出自《三国演义》） | **正文不回答**；演义说黄盖；裴松之注引《山阳公载记》说是**刘备**烧的；《吴主传》里曹操自己写信说「孤烧船自退，横使周瑜虚获此名」。后两说都不在本篇这三段里 |

**为什么这么定**：读者记得住的版本就是他要核对的版本。把它摆出来、标清出处，
再告诉他「另有几说」——比只写一句「史书不回答」有用得多，也比平铺三说更好读。
**代价是依据栏会变长，这是值的。**

### 一之补四、「依据」栏里的编号，读者要能在本篇「原文」页签里查到

种子的「依据」和复习卡的「依据」，意思都是「这条回答凭什么」。那一栏里写了编号，
读者就会去「原文」页签核——而页签里只有本篇声明范围内的段落。
**引了范围外的编号，指针就是断的。**

两种情况，两种改法：

- **跨篇指路**（荆轲那几篇是链式的，06-yishui 的时间线卡要引 05-taizidan 的编号）：
  写清是哪一篇——「（承 `05-taizidan`）」——别只丢一个编号。
- **真的要摊给读者看**：把编号补进 `stories.md` 的「原文」那一列，
  那等于承认这一段要进「本篇原文」。

编译器会报提醒（2026-10-15 全库 131 处，绝大多数是荆轲的跨篇指路），不拦。
**不拦是有意的**：荆轲那几篇的交叉指路是正当写法，硬拦会逼作者少交代一层。

### 一之补五、范围外 ≠ 不存在

**引文（含卡片正文里不带编号的引文）必须落在 `stories.md` 那一列声明的范围里。**
写在范围外、又不带编号的引文，编译器结构上永远查不到你——02 的卡片就是这么把
演义第四回中牟段的两句话引进来的。

更要紧的是措辞。`103` 是从一段 **545 字**的《曹瞒传》裴注里裁出来的；把它当成
「这本书的全部」，就会写出下面这种假话：

| 错的写法 | 为什么错 | 该写的 |
|---|---|---|
| 「正文止于『大破琼等，皆斩之』」 | 《武帝纪》正文**接着还有**张郃高览来降、绍众大溃 | 「**本篇这三段**写到『大破琼等，皆斩之』为止」 |
| 「底本不写杀了几个人」 | 《曹瞒传》写了（割鼻、杀千余人、许攸一句话定他的死） | 「`011` 不写」或「不在本篇范围内」 |
| 「『乌巢』是后世的称法」 | 乌巢见于裴注原文（「在故市、乌巢」） | 「这三段里没有地名；乌巢见于裴注的上下文」 |

**判据一句话：凡是「我们没裁进这几段」的，一律说「本篇这三段里没有」，
不许说「底本不写」「正文止于」「后世才有」。** 声明了范围，就要有一条种子或
一行映射表交代范围外最可能被追问的那件事（08 就是张郃高览——全库零命中）。

### 二、不要重复标记本身

❌ `| 依据 | ◆ 原文。一字不可改。 |`
✅ `| 依据 | \`056\`「壮士一去兮不复还」 |`

**标记已经说了的话，不要再写一遍。**

### 三、台词的语言形式是全局规则，不逐条标注

**人物说出口的话一律是现代汉语改写，不可逐字核对。** 这是全局事实，写在产品里一次就够，不需要每条回答都注一遍。

### 四、`依据` 只回答一个问题：这条回答凭什么

| 标记 | `依据` 里写什么 |
|---|---|
| ◆ | 原文编号 ＋ 原句 |
| ○ | 推演链条（从哪些原文推出来的） |
| △ | 后世的主要说法 |
| — | **不写**（沉默本身就是答案） |

### 五、审校记录不写进内容

「原稿写错了」「已改」这类话属于审校过程，**不属于产品内容**。
它们记在 `../审校记录.md`，不进这里。

### 六、`内部` 字段不渲染

写这条回答时**为什么这么写、边界在哪里**（如「这里不能让他显得不认识高渐离」），
写进 `| 内部 | ... |`。编译器会读它、**界面永远不显示**。

（这一栏原来是给 M2b 的系统提示词准备的（硬拦截规则）；**M2b 已取消**——
不做 AI 自由对话。现在它是**给下一个写内容的人看的判断留档**，
内容本身仍然是静态的、人工审校过的。全库 `内部` 栏见 `grep -rn '| 内部 |' content/people/`。）

## 核对口径：核到哪一层，为什么到此为止

先分清两层，因为「没核实体书」这句话很容易被读成「什么都没核」：

| | 核的是什么 | 拿什么核 | 状态 |
|---|---|---|---|
| **第一层** | 本库写的字，和那份公版电子本是否一致 | Gutenberg《三國志》#25606（含裴注）、《三國志演義》#23950、《史記》#24226、GitHub `hunterhug/china-history`〈刺客列传〉、维基文库《北齊書》《魏書》《周書》《晋书》《梁書》《宋書》《宋史》各卷 | **全库 七百七十一段做完**（2026-10-20；段数会变，以 `npm run check-sources` 的输出为准） |
| **第二层** | 那份电子本本身是否可信 | 中华书局点校本那类排印本 | **不做**（见下） |

**第二层不做，是一个决定，不是一件待办。** 手上没有点校本，
而这条缺口不会因为再等下去而缩小：`web_search` 插件至今认证失败（401）、
中文维基文库本机直连不通（只能经只读文本代理取到，取到的页面修订号与哈希都记在
`.refs/manifest.json`）、ctext.org 明确禁止抓取。
**所以本库的口径就定在第一层**——底本逐字以公版电子本为准，
谁都能 `npm run refs` 重新下载、`npm run check-sources` 自己复核一遍。

**已知第一层挡不住什么**（写在这里，免得以后有人以为它挡得住）：

- 电子本自己会错。曹操那篇抓到 5 处（校勘表里登着：`砲→炮`、`马赢→马羸`、
  `拄→拿` 等），这 5 处是按「通行本应该是什么」改的。
- Gutenberg 的《史記》#24226 **整个缺〈刺客列传〉**，荆轲那 93 段换用 GitHub
  上一份转录本才核成。同一部书换一份文件就可能换一批字。
- **我们和电子本一致的时候，两边一起错是看不出来的。** 第一层能证明「不是我们抄错」，
  证明不了「这段原文本来就是这五个字」。

## 代码里那个「核对优先级」字段

`source.md` 每段带一个 A／B／C，标记的是「**先看哪里**」，**不是「哪里已经确认正确」**。
它给人工抽读排队用，**别把它读成质量等级**。分布（2026-10-17 数的，会随收底本变）：

| 优先级 | 曹操 | 荆轲 | 建议动作 |
|---|---|---|---|
| A | 125 段 | 59 段 | 扫一眼即可 |
| B | 111 段 | 28 段 | 略读，留意可疑处 |
| C | — | 6 段（`010` `013` `014` `015` `060` `080`） | ⚠️ 逐字看 |

（曹操的 B 是裴松之注那一档——**注整档算 B**，不是"可疑"的意思。）

> ⚠️ 这一列原来是按「名句／常见度」推「文本稳定度」定的，**那个逻辑是错的**：
> 名句恰恰是被引用、改写、串味最多的地方。独立复核员给的机制很具体——
> 荆轲 `057`「复为羽声**忼**慨」很可能来自《项羽本纪》「悲歌**忼**慨」，
> **正因为这两个字太常见，才被串了味。** 已改：优先级只表示"先查哪里"。

**你的审校从荆轲那 6 段 C 开始，不要从头读。** 另有 15 处待核疑点
（复核员提出、无法验证，只标记不修改）和 27 处 `★` 叙事关键句。

## 格式和设计文档里说的不一样（**以本节为准**）

设计文档 §6 写的是 YAML。**实际用的是 Markdown**，并且一直是 Markdown——
编译器（`web/scripts/build-content.mjs`）**直接读 Markdown**，
没有「转 YAML」这一步，也不需要。

理由（M1 时定的，现在仍然成立）：**格式必须服务读它的人。**
如果交给你一个 700 行的 YAML，你会打开、看到缩进和冒号、关掉。
内容项目最常见的死法不是写不出来，是**写出来了但没人真的读过**。

> 🕘 **历史**：这一节原来还有一句「等 M2 需要代码消费这些内容时，Markdown → YAML
> 是纯机械转换，我会做」。M2 之后并没有转——编译器直接解析 Markdown，转一层反而
> 多一份会走样的副本。**单一数据源没有变：源就是 `content/**/*.md`。**

## 三个核心概念

### 1. 知识边界：三档

**这是写内容时最要紧的一条纪律**（原来打算当作 AI 扮演的硬约束——
见本节末尾的 🕘 历史说明；**现在产品里没有 AI**，这条约束靠人写、靠审校兜住）。

| 档 | 含义 | 标记 | 写内容时的做法 |
|---|---|---|---|
| **知** | 史书明载 | ◆ 出自原文 | 可直说，可逐字核对 |
| **度** | 史书未载但可推度 | ○ 合理推演 | 可说，但**必须交代推度链条** |
| **禁** | 此刻绝不可能知道 | — | **不许出现在回答里**（读者问到时，用 `—` 或 `ⓘ` 正面交代） |

**「禁」是产品存在的原因。**

没有它，荆轲会说出"我死后高渐离会去刺秦王"——这句话足够动人，足够让你记一辈子，而它是假的。

> 🕘 **历史**：这一段原来写的是「没有它，**AI 会让**荆轲说出…」，并把这套三档称为
> 「整个项目的技术核心」，因为当时计划用提示词硬拦截模型。**该计划已取消**
> （2026-10-17：不做 AI 自由对话）。现在这三档的用处是把关写作：
> 种子和复习卡里凡是碰到「他此刻不可能知道的事」，要么给 `—`，要么给 `ⓘ`，
> **不许写成 ○ 或 ◆**。`cast.md` 里的「禁」一档就是这份清单。

### 2. 六个标记

| 标记 | 色 | 含义 | 用户该学到什么 |
|---|---|---|---|
| ◆ | 朱 | 出自原文，**可逐字核对** | 这句能查证 |
| **◇** | **紫** | 出自**小说**（《三国演义》），不是史书 | 这是另一本书里的说法 |
| ○ | 苍 | 史书未载但可推度，**须展示链条** | 这是推出来的，看看链条合不合理 |
| △ | 赭 | 史书未载且**后世有争议** | 这里有两说，别当定论 |
| **—** | 灰 | 史书未载，**且无法推演** | **有些问题没有答案** |
| ⓘ | 中性灰 | **产品说明**：回答的是产品本身 | 这一条不问史料 |

**◇ 和 ⓘ 都不在那把尺子上。** ◆ ○ △ — 说的是「这句话在史料上站得住多少」；
◇ 说的是「这句话出自哪本书」；ⓘ 说的是「这条回答跟史料无关」。
详见上面「标记不止四个（现在是六个）」。

**硬规则：任何一条回答必须落在这六个之一。落不进去的，说明这条回答不该存在。**

### 3. 写作规则（写内容时必须遵守）

> **背景**：第一版把「审校文档」和「产品内容」写成了一份东西，
> 结果用户界面里出现了「原稿标 △ 是错的」「已改」「一字不可改」这类话，约 130 处。
> 现在拆开了：**内容文件只放产品内容，审校过程一律进 [`审校记录.md`](审校记录.md)。**

| 规则 | 说明 |
|---|---|
| **一条回答只标一个标记** | 标记表示**回答内容**在史料上的地位，不表示语言形式 |
| **不要重复标记本身** | ❌ 依据写「◆ 原文。一字不可改。」　✅ 依据写「`056`『壮士一去兮不复还』」 |
| **台词改写是全局规则** | 「人物说出口的话一律是改写」在产品里说一次就够，不逐条标注 |
| **`依据` 只回答"凭什么"** | ◆ 给编号＋原句；○ 给推演链条；△ 给异说；`—` **不写** |
| **审校批注不进内容** | 「原稿」「已改」「是错的」一律不许出现 |
| **`内部` 字段不渲染** | 写这条时**为什么这么写、边界在哪**，写进 `\| 内部 \| ... \|`（原是给 M2b 提示词的，M2b 已取消；现在只作为给下一个写作者的留档） |

**编译器会强制检查**：`依据`／`备注` 里出现「原稿」「已改」「是错的」「一字不可改」会直接报错，并列出是哪几条。

> ### ⚠️ 第四档「—」是本轮新增的（原稿说只有三类）
>
> 产品其实**早就在用它**了——`04` 的太子丹那行、`05` 的两道陷阱题，用的都是"史书的沉默"。只是文档一直声称只有三档。
>
> **为什么必须正式拆开**：不拆的话，△ 会被拿来装"我们决定不回答"，于是 **△ 从"史料有争议"退化成"产品不知道"**——而"知道哪些问题没有答案"恰恰是这个产品的核心教学点（见 `people/jingke/cards/06-yishui.md` 两道陷阱题）。
>
> **混用会让这个教学点失效**：用户会以为"史书没写"也是一种"有争议"。
>
> **事实层与台词层也要分开**：人物说出口的话一律 ○（现代汉语改写，不可逐字核对）；支撑它的事实才标 ◆。只有原文原句直接进入回答时，台词层才能标 ◆。 **台词出自小说时标 ◇**——它说的不是"这句话多可靠"，是"这句话出自哪本书"，两回事，别混。详见 `people/jingke/stories/06-yishui.md` 的标注规则。

### 3. 叙事压缩

你举的例子（"悼文可以简化为 A 为 B 写悼文，说 B 生前忠孝、屡立战功"）已经固化成规则，见 `people/jingke/stories.md`。

一句话：**名句、名喻、推动情节的话必须保留原貌；程式化文书、重复对话、礼仪流程压成概述。**

**红线：概述只能省略细节，不能添加原文没有的信息，也不能改变因果方向。**

## 这一轮我发现的三件事

> 🕘 **历史（2026-10-13 前后）**——写内容时冒出来的三个发现。
> 当时的表述用了「AI 会…」「硬拦截」这套说法（那时还打算做 AI 扮演）；

> 第 3 条（「不是刺客，是去签合同的」）后来被 R04 修过一次——**比喻和自述的性质要分开说**，
> 别把现代比喻写成定论；见 `docs/问题清单与研发整改任务书-2026-10-17.md` R04。

写内容的过程中冒出来的，都值得你知道：

### 1. 高渐离和秦舞阳，在《刺客列传》里一句话都没说过

我核对了一遍。**这两个角色在《刺客列传》里零台词。**

> 范围限于《刺客列传》。《秦始皇本纪》《燕召公世家》等其他篇目**未纳入核对**，所以不写"《史记》全篇"。

- **高渐离**只有动作：击筑、评论别人的筑声、被熏瞎眼后仍击筑、**把铅灌进筑里扑向秦始皇**
- **秦舞阳**只有三行记载：年十三杀人、人不敢忤视、**至陛色变振恐**

这不是资料不足的缺陷，**这是产品最有价值的推演入口**。一个从不说话的人，最后用乐器去砸皇帝——史书对他为什么这么做，一个字都没解释。

### 2. 秦舞阳的"怕"，发生在未来

史书给了这个角色一个巨大反差——十三岁杀人的勇士，到了秦国宫殿台阶下**脸色变了、浑身发抖**。

但那个反差发生在**下一步**。在易水边，他还是个自信的勇士。

**如果 AI 让他此刻就表现出恐惧，就是穿越。** 这是他的人物卡里最重要的一条硬拦截，也是「知识边界」机制最有说服力的一次演示。

### 3. 荆轲不是刺客，他是去签合同的

太子丹的原话是：**劫持秦王、逼他归还侵占的土地，那最好；不行，才刺杀**（`032`）。

荆轲临死前说的也是同一件事：**「以欲生劫之，必得约契以报太子也」**（`075`）。

这两段是一对。大多数人以为他是刺客，其实他是去执行一份合同的——**任务失败的原因不是他不够狠，是他还想签成。**

## 一篇故事该满足什么（2026-10-15 · 用户连着撞出四五个「最基础的错」之后写的）

**这份清单是「一篇东西该满足什么」，不是「我见过的错」。** 分成两栏——
**机器判得了的**进闸门；**判不了的**每次交出去之前，我自己按它逐条读一遍。

### 一、机器判得了的（都已进 `npm run check`）

| 条 | 判据 | 闸门 |
|---|---|---|
| 引文逐字对得上底本 | 每段 ≥4 汉字的「」要能在所引编号里找到 | ✓ |
| 引文归属 | 一行只引一个编号时，该行 ≥6 字的「」都要命中它 | ✓ |
| 拼接引文 | 整行引号、不在任何一段里、但按标点切开每截都在 → 红 | ✓ |
| 范围变更要同步 | 范围变了而 seeds/cards 指纹没变 → 红 | ✓ |
| **两篇不许大段重复** | B 篇正文的 8 字窗口有多少能在 A 篇里找到，**≥30% 红** | ✓ |
| **范围里声明的段要真的用上** | 声明的编号必须被铺陈、情节点或背景卡实际引用；不能只列在范围里 | **待补** |
| **原文块不许是整段注** | 单块 >150 字 → 红（要引的是「那件事的那一句」） | **待补** |
| 门口是简介不是正文 | ≤8 行 | ✓ |
| 依据是「这一行从哪来」 | ≤90 字 | ✓ |
| 读者面前不许有写给作者的话 | 待办／改稿史／内部行话 | ✓（内容＋界面两条） |
| 读者可见字段不许有产品自述 | 「本产品」「这一页」… | ✓ |
| 一卡一标记、每卡有考点 | | ✓ |
| 标记分布表要对账 | | ✓ |

### 二、机器判不了的（每次交出去之前，逐条读）

**铺陈与开篇的分工（2026-10-18）：** 铺陈应让读者明白人物此时是谁、为何来到这里、眼前有什么难处。通常三小段、五六句话足以起步；这是编辑尺度，不是凑句数的指标。上限 8 行含时间地点，手机上的自动换行不计。不要预告整篇经过或结局，也不要压成一句家世、口号或空泛悬念。

**把铺陈和正文首段连起来读。** 必要前情可移入铺陈，让正文从新的动作开始；名册、官职解释和详细考据放背景与依据，保留可查入口。若首段重复铺陈，应调整二者的分工，不能一律删铺陈。不同故事不必都用问句收尾，不编人物心声或现场细节。

**依据也要跟着当前情节走。** 「原文」栏的摘句只有连续逐字命中对应编号时，才可先显示摘句、折叠完整底本；匹配失败则显示全文。多个来源必须逐一保留，不用一个摘句替代其他段落的证据。

1. **白话不许是回译的复述** —— 「用词不同、意思相同」也算。
   （机器试过：4 字滑窗只抓得到 10/165，用户一眼看到的那条抓不到 ✗）
2. **哪一句值得给原文** —— 人物说出口的话 · 出名的句子 · 他自己写的东西。
   **记事一律白话。** 拿不准就算不值得，宁少勿多。
3. **原文块只给「那件事的那一句」，不给整段注** —— 上一轮把 145 字的孙盛注整段当原文块，
   把「子治世之能臣，乱世之奸雄」埋在最末尾 ✗
4. **一篇的切角** —— 它讲的是哪一件事？和相邻的篇**是不是在讲同一件事**？
   （`03-chenliu` 曾经 71% 的正文能在 `02-cidong` 里逐字找到 ✗）
5. **度** —— 荆轲是标准：**原文块只给有气势、出名的句子**，其余白话。
   量过的比例：荆轲 14 个原文块 / 66 个情节点；曹操现在 40 / 161。

### 三、每次交出去之前，我自己要跑的三步

1. `npm run check` ＋ `npm run check-sources`（机器）
2. **按第二栏逐条读一遍**（至少读第一个情节点和最后一个）
3. **量三个数报给用户**：原文块数 · 和相邻篇的重复率 · 情节点数

**第 2 步是「用户指一处、我改一处」的解药**——他撞出来的错全在第二栏，

### 原文内部的出处分层

同一编号内混有正文和注，或同一条裴注合引多书时，可用人物目录中的`source-layers.json`逐片登记`tier`、`origin`、`text`和`gloss`。界面据此标明出处，原编号、引用目标与阅读记录不变。正文、注体、引书和按语的边界须先对照带注版本人工核定，不能由编号或关键词自动判定。

`source.md`与`gloss.md`仍保存完整文字。分层的原文与白话必须分别逐字拼回两份总稿；编译遇到缺字、重复、错序或白话漂移会失败，不能另写一份较顺的“原文”。修改白话还需同步`gloss-parts/`，运行`npm run test:sources`检查真实材料与分片。此项校验保证分层无损，不证明史料真实或校勘完整。
