## 二、剩下的活，和为什么是这个顺序

```
①  范围戳闸门          ← 先做。它是后面所有活的绳子
②  修 08-guandu 的种子卡  ← 闸门一立，它自己会列出来
─────────────────────────────────────────────
③  九篇正文重做         ← 你真正要的东西（故事不简陋）
④  十篇种子卡跟上
─────────────────────────────────────────────
⑤  直译 223 段          ← 完整资料入口的内容
⑥  完整资料入口界面
─────────────────────────────────────────────
⑦  页面瘦身（顺手）      405 KB → 约 120 KB
```

### 为什么 ① 必须排在 ③ 前面

③ 会**改每一篇的原文范围**。范围一变，那一篇的种子卡里所有「本篇这几段」
「X 不在本篇里」的说法就全变成假话——**而编译器一声不响**。

今天 08-guandu 就是这样：底本从 3 段扩到 14 段之后，种子里十来处说法全部失效，
没有任何东西报警。**九篇重做 = 同样的错来九遍。**

先把闸门立起来，③ 才敢走。

## 三、每一步怎么做（含安全设计）

### ① 范围戳闸门

**做什么。** 每个种子/卡片文件顶部写一行「本文件对着的范围：`040–045`、`244`」。
编译器拿它和故事一览的「原文」列比，**不一样就红**：

```
✗ 08-guandu 的种子是对着旧范围（`011`–`012`、`103`）写的，
  现在是（`040`–`045`、`244`）。范围变了，话要跟着重读一遍。
```

**为什么用「戳」而不是「查措辞」。** 查措辞只抓得住数得出来的（「本篇这三段」），
抓不住「许攸一个字也没有」这种语义上的假话。**戳检测的是「陈旧」，不是「对错」**——
范围一变，不管假话是什么形态，全部报红。

再加一条计数检查当补充：「本篇这三段」里的数字 vs 范围实际段数。

**安全设计：**
- 只加一条校验 + 一个字段，**不改任何内容**
- 加完先跑一遍，**看它在 08-guandu 上报出什么**——报不出来说明闸门是死的
- **故意写坏一处，确认它会红**（负向测试）
- 做完提交

**你怎么验：** `npm run check` 应该红，且只红在 08-guandu 上。

### ② 修 08-guandu 的种子卡

**做什么。** 照闸门列出来的位置逐条改。这批假话是**具体的、可数的**，改完闸门归绿。

**安全设计：**
- 只动 `seeds/08-guandu.md` 和 `cards/08-guandu.md` 两个文件
- 改完 `check` + `check-sources` 全绿

**你怎么验：** 我可以把改动前后的对照列给你。

### ③ 九篇正文重做（最大的一块）

**做什么。** 照官渡的标准：**第一个情节点不能就是转折点，最后一个不能停在转折点上**。
每篇补底本里的前因与后果，情节点从 2–4 段扩到 7–9 段。

**安全设计（这块最容易出问题，所以拆得最细）：**
- **一篇一个提交。** 不做「九篇一起改完再提」
- **一篇一个子智能体**，每篇的活是独立的
- 每篇做完：`check` + `check-sources` 全绿 + **截图给你看**
- **你看完说行，我才开下一篇**（前两篇）；后面可以批量
- 子智能体只动那一篇的文件，**不许碰别篇**（这条写进它的任务书）

**你怎么验：** 每篇的截图 + `npm run check`。

### ④ 十篇种子卡跟上

**做什么。** 正文变了，种子和卡引的编号、「本篇这几段」都要跟着变。
**闸门（①）会把该改的位置全部列出来。**

**安全设计：** 一篇一个提交，闸门归绿才算完。

### ⑤ 直译 223 段

**做什么。** 给每段底本配一条**直接译文**，放 `content/people/<id>/gloss.md`

**你怎么验：** 抽几段对着原文读。
